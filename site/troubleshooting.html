문제 해결

자주 겪는 증상

증상을 누르면 원인과 조치가 펼쳐집니다. 로그는 ~/.local/state/kakaotalk.log에 남습니다.

증상별

자주 겪는 증상

카톡 창이 안 뜨고 프로세스만 있어요
XWayland 창 관리자가 고장난 상태입니다. 간단한 X11 창도 안 뜨면 확실합니다. omarchy system logout 후 다시 로그인합니다. Xwayland를 종료해도 다시 시작되지 않습니다.
카톡이 통째로 종료되고 로그에 MEPF_REWRAP이 있어요
기본 Wine riched20의 단정문입니다. tools/build-riched20.sh로 패치하고 tools/riched20-selftest.sh가 PASS인지 확인한 뒤 카톡을 재시작합니다. 원인과 패치
채팅 중 커서가 튀거나 다른 창이 클릭돼요
손바닥이 트랙패드를 탭한 것입니다. hyprland-kakaotalk.lua의 타이핑 중 탭 막기 부분이 hyprland.lua에 들어갔는지 확인합니다. 자세히
카톡 창이 사라졌어요
트레이로 숨은 것입니다. 바 아이콘을 누르거나 kakaotalk을 다시 실행합니다.
복사한 파일을 붙여넣으면 경로만 들어가요
카톡 창에 포커스가 있을 때 hyprctl binds에 KakaoTalk: paste copied files as attachments가 있는지 확인합니다. 없으면 config/hypr/hyprland-kakaotalk.lua의 Ctrl+V 부분이 hyprland.lua에 들어갔는지, dropfiles.py가 ~/.local/share/kakaotalk-ec/py/에 있는지 봅니다. 바인딩이 있는데도 경로가 붙으면 포커스된 카톡 창을 Wine 쪽에서 찾지 못해 원래 Ctrl+V를 넘긴 것입니다. 채팅방 창을 한 번 클릭한 뒤 다시 누릅니다.
새 메시지 알림이 안 와요
pgrep -f '[k]akaotalk-notify'에 PID가 나오는지 봅니다. 없으면 command -v inotifywait로 inotifywait(inotify-tools 패키지)가 설치됐는지 확인하고 setsid -f ~/.local/bin/kakaotalk-notify로 띄웁니다. 카톡 창에 포커스가 있을 때는 원래 알리지 않습니다. 카톡에 처음 로그인한 뒤에는 채팅 폴더를 찾기까지 최대 30초가 걸립니다. 자세히
로그아웃/로그인 뒤 wireplumber가 CPU 100%예요
wireplumber 0.5.17의 루프 버그입니다. systemctl --user kill --signal=KILL wireplumber && systemctl --user restart wireplumber로 풉니다.
바에 아이콘이 안 보여요
omarchy restart shell을 실행합니다.
pkill -f를 쓰면 셸이 같이 죽어요
패턴이 자기 셸의 명령줄에도 매칭되기 때문입니다. [k]akaotalk처럼 대괄호 형태로 씁니다.
