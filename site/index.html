Omarchy · Asahi Linux · Apple Silicon

Apple Silicon 맥의 Omarchy에서 카카오톡 쓰기

16K 페이지 ARM 리눅스에서 Windows용 카카오톡 32비트 클라이언트를 ARM64EC Wine과 FEX로 네이티브 실행합니다. 한글 입력, 스크린샷·파일 붙여넣기, 바 아이콘, 입력창 크래시 패치까지 맞춘 설정 기록입니다.

결론 요약

무엇이 되고 무엇이 안 되나

x86_64용 가이드(Bottles, Soda)는 ARM 맥에 쓸 수 없습니다. 여러 방식을 시험해 보고 남은 조합은 하나입니다.

방식결과
Bottles + Soda (minpeter 가이드)실패 모두 x86 전용
muvm + FEX + x86 Wine실패 32비트는 로그인 후 흰 창, 64비트는 Themida로 보호된 Vox3.dll에서 크래시
ARM64EC Wine 11.18 + FEX wow64, 32비트 클라이언트동작함 muvm 없이 16K 호스트에서 네이티브 실행
같은 방식 + 64비트 클라이언트실패 Themida로 보호된 Vox.dll에서 실행 위반

카카오톡 바이너리와 계정 정보는 저장소에 들어 있지 않습니다. 설치 파일은 카카오 CDN에서 받습니다. Wine은 시스템에 설치하지 않고 lacamar/wine-arm64ec COPR의 RPM을 풀어서 씁니다.

한계와 라이선스

알아 둘 점

  • 64비트 클라이언트는 Themida 때문에 쓸 수 없습니다.
  • 통화는 충분히 검증하지 않았습니다.
  • 알림은 "새 메시지"라는 기본 알림뿐입니다. 이 환경의 32비트 카톡은 알림 창을 만들지 않아서 보낸 사람, 방 이름, 내용은 보여 줄 수 없습니다.
  • riched20 패치는 Wine 11.18 기준입니다. 다른 버전은 다시 빌드해야 합니다.
  • 바 아이콘에는 안 읽은 메시지 표시가 없습니다.
  • 파일 붙여넣기는 Wine을 한 번 띄우므로 확인 창까지 1~2초 걸립니다.

스크립트와 문서는 MIT 라이선스입니다. 예외로 wine/fontlink.py는 chaotic-ground/kakaotalk-on-wine의 코드를 고친 것이라 GPL-3.0-or-later를 따릅니다. wine/riched20-cursor-coords-rewrap.patch는 Wine 소스를 고친 것이라 LGPL-2.1-or-later입니다. 일부 설정은 minpeter/omarchy-kakaotalk을 참고했습니다.
